GETTING STARTED

The basic EvalLoop evaluation flow.

Evaluate an AI response with EVP.Aureon

EvalLoop AI currently provides a general-purpose evaluation flow through EVP.Aureon. The evaluator receives the original prompt, the AI-generated response, and an optional reference answer.

It evaluates the supplied response across six dimensions, normalizes the dimension scores to a 0–100 range, and returns a calculated overall score together with issues, summary, and recommendation.

EVALUATION FLOW
TARGET PROMPT ↓ AI RESPONSE ↓ OPTIONAL REFERENCE ↓ EVP.AUREON ↓ SIX EVALUATION DIMENSIONS ↓ OVERALL SCORE ↓ ISSUES + SUMMARY + RECOMMENDATION
EVALUATION DIMENSIONS

EVP.Aureon currently evaluates six core dimensions. Each dimension produces a score from 0 to 100.

Six dimensions. One quality signal.

The current evaluator uses six dimensions to provide a structured view of AI response quality.

Factuality

Measures whether the response is factually accurate and avoids unsupported claims.

Instruction Following

Measures whether the response follows the user's stated instructions and requirements.

Relevance

Measures how directly the response addresses the requested task or question.

Completeness

Measures whether the response adequately covers the important parts of the requested task.

Safety

Measures whether the response avoids relevant safety failures and harmful behavior.

Fluency

Measures clarity, readability, language quality, and overall response fluency.

BENCHMARKS

A benchmark runs a defined dataset through a target AI system and evaluates the resulting responses.

Benchmark architecture

EvalLoop AI benchmarks are designed to separate the target AI system from the evaluation engine. The target system generates responses, while the evaluation engine measures those responses against the selected benchmark criteria.

BENCHMARK FLOW
TARGET AI SYSTEM ↓ CUSTOM API / PROVIDER API / UPLOAD ↓ BENCHMARK DATASET ↓ TARGET AI GENERATES RESPONSES ↓ EVP.AUREON ↓ DIMENSION SCORES ↓ BENCHMARK RESULT ↓ HISTORY

The current benchmark experience is centered on General Quality evaluation. Specialized benchmark engines and suites are planned for future releases.

API

Current evaluation API endpoint and request/response format.

Evaluate a response

POST /api/evaluate

Send an AI prompt and its generated response to the EvalLoop evaluator. A reference answer can optionally be supplied to provide additional evaluation context.

REQUEST
{ "prompt": "What is the capital of France?", "response": "The capital of France is Paris.", "reference": "France's capital city is Paris." }

The request must use JSON. The prompt and response fields are required non-empty strings. The reference field is optional.

Evaluation response

A successful evaluation returns the overall score, the six dimension scores, detected issues, a summary, and a recommendation.

RESPONSE
{ "overall_score": 100, "overall_text": "Strong response.", "scores": { "factuality": 100, "instruction_following": 100, "relevance": 100, "completeness": 100, "safety": 100, "fluency": 100 }, "issues": [], "summary": "The response accurately answers the user's question.", "recommendation": "No major improvements are required." }
Important: The example scores and text are illustrative. Actual evaluation results depend on the supplied prompt, response, reference, and evaluator output.

Overall score calculation

The backend does not trust an overall score supplied by the evaluator model. It calculates the final overall score from the six normalized dimension scores.

CALCULATION
overall_score = ROUND( ( factuality + instruction_following + relevance + completeness + safety + fluency ) / 6 )

Each dimension is normalized to an integer from 0 to 100 before the overall score is calculated.

Evaluation issues

The evaluator can return up to ten issues. Each issue contains a type and description.

ISSUE FORMAT
{ "type": "factuality", "description": "The response contains an unsupported claim." }

Invalid issue entries are filtered by the backend before the final response is returned.

API errors

The current endpoint returns standard HTTP error responses for invalid requests, configuration failures, upstream evaluation failures, and unexpected server errors.

  • 405 — Method not allowed.
  • 400 — Prompt is required.
  • 400 — AI response is required.
  • 500 — GROQ_API_KEY is not configured.
  • 502 — Groq evaluation request failed.
  • 502 — Groq returned an empty response.
  • 502 — Groq returned invalid evaluation JSON.
  • 500 — Unexpected server error.

Current API scope

The current /api/evaluate endpoint evaluates a prompt and response supplied directly in the request. It does not currently act as a general-purpose proxy for arbitrary external AI provider APIs.

Benchmark target connections and provider integrations are part of the broader benchmark architecture and may require additional implementation.

SECURITY

Keep provider credentials on the server and never expose secret API keys in client-side code.

Server-side credentials

The current evaluation backend reads the Groq API credential from the server-side environment variable GROQ_API_KEY.

Never expose GROQ_API_KEY in browser JavaScript, public HTML, GitHub repositories, or client-side configuration.

Client applications should communicate with the EvalLoop backend endpoint rather than embedding provider credentials in the browser.

Evaluation provider

The current evaluator uses Groq's OpenAI-compatible chat completions endpoint with the configured evaluation model. The provider credential remains on the server.

Future evaluation profiles and benchmark integrations may introduce additional providers or execution paths as the EvalLoop platform develops.
